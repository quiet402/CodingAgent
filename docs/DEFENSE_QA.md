# 面试答辩准备

## 30 秒设计概述

CodingAgent 是一个显式状态机：把系统规则、用户任务和历史交给模型；模型返回原生 tool calls；本地注册表校验并执行工具；结果以 tool message 回传，直到模型返回最终文本。我的重点不是功能数量，而是循环在错误、长上下文和重复调用下仍然可解释、可停止、可审计。

## 高频问题

### 1. 为什么不用 agent 框架？

题目要求核心逻辑自行实现。直接实现协议能清楚展示状态如何流动，也能控制上下文配对、错误语义和停止条件；代价是需要自己维护兼容性和可观测性。

### 2. Agent 为什么会“继续转”？

每轮模型要么返回最终文本，要么返回工具调用。工具执行结果被追加为带相同 `tool_call_id` 的消息，再次请求模型。因此模型能看到真实环境变化并决定下一步。这是一个显式的反馈闭环，不是递归黑盒。

### 3. 怎么保证不会无限循环？

有四层边界：正常最终文本、最大轮次、六次连续工具错误预算、第三次连续相同工具调用熔断。Ctrl+C 还提供人工终止。所有退出路径都有 `stop_reason`。

### 4. 为什么重复调用第三次才拦，而不是第二次？

第二次可能是合理重试，例如文件刚被修改后重新读取。连续三次工具名和规范化参数完全相同，更可能是模型卡住。熔断结果仍回传给模型，让它有一次改变策略的机会。

### 5. 如何处理长上下文？

系统提示和原始任务固定保留。其余消息按 assistant 响应及其 tool 结果成块，从新到旧装入字符预算；淘汰的完整块生成确定性摘要。这样不会产生孤立 tool 消息。字符预算跨模型通用，但精度不如 tokenizer，这是刻意的依赖折中。

### 6. 为什么写文件还要 `overwrite=true`？

这是让高风险意图显式化。新建和覆盖不是同一种动作；模型若要覆盖，应先读文件，再明确声明。精确替换还要求匹配次数正确，失败时保持原文件不变。

### 7. 如何防止访问工作区外文件？

所有文件路径都会相对根目录解析并规范化，再用 `relative_to` 验证边界，所以 `../`、绝对外部路径以及已存在的符号链接跳转都会被拒绝。命令层另外阻止父目录参数和外部绝对路径。

### 8. 安全模式是不是绝对安全？

不是。它是防误操作策略，不是 OS 沙箱。允许的测试程序会执行项目代码。更强保证需要容器、低权限用户、网络隔离与资源限额。项目在 README 中明确说明这个边界。

### 9. API 出错怎么办？

429、5xx、网络异常和超时使用有限指数退避；其他 4xx 不盲目重试。重试耗尽会以 `model_error` 停止。工具异常则被隔离为失败 observation，不导致主进程崩溃。

### 10. 为什么不使用厂商 SDK？

题目允许 SDK，但不是必须。本项目直接实现兼容的 HTTP 协议，减少安装依赖，并能说明每个字段如何进入循环。代价是只覆盖本项目需要的 Chat Completions/tool calling 子集。

### 11. 怎么测试非确定性模型？

把模型抽象为一个很小的 `ModelClient` 协议。单测注入脚本化响应，精确验证“模型调用—工具执行—结果回传—完成”的行为；真实模型联调只作为额外验收，不承担核心回归测试。

### 12. 审计轨迹会不会泄密？

配置中不记录 API key；审计层还会按字段名屏蔽 key/token/secret/password/authorization，并替换常见 `sk-...` 和 Bearer 形式。它是纵深防御，用户仍不应把密钥写进任务或文件。

### 13. 流式输出时如何处理 tool call？

Chat Completions 会把函数 ID、名称和参数拆成多个 delta。客户端按 tool call 的 `index` 分桶，将各字段分别追加；收到 `[DONE]` 后才交给工具注册表。文本 delta 则立即输出。若已经输出部分内容后连接中断，不自动重试，避免重复显示或重复执行。

### 14. 连续会话如何工作？

一个 `AgentRunner` 持有一个 `ConversationHistory` 和审计文件。首个任务创建历史，之后每条 `forge>` 输入追加新的 user 消息，再执行一轮完整 agent 循环。`/new` 会同时清空历史并创建新审计文件，`/quit` 才退出进程。

### 15. DeepSeek 为什么不能只改 base URL？

地址和模型名确实兼容 Chat Completions，但思考模式会额外返回 `reasoning_content`。在携带工具的后续请求中，DeepSeek 要求完整回传此前 assistant 的这个字段，否则可能返回 400。客户端同时适配非流式字段和流式 delta；它不会在终端展示内部推理，只在协议历史里保存并回传。provider 预设还集中管理当前模型名、专用密钥变量和思考强度，避免每次手工配置。

### 16. 退出后如何恢复会话？

每个用户回合以及完整工具批次结束后，Agent 会在协议安全点原子保存未压缩历史。`/sessions` 按更新时间列出本工作区会话，`/resume ID` 支持完整 ID、唯一前缀或 `latest`。加载时校验格式版本、文件名、工作区和 provider，防止路径穿越或把别的项目历史误接进来。恢复文件不保存 API Key，但会保存对话、工具输出和推理上下文，因此 `.forge` 仍应作为本机私有数据处理。

### 17. 为什么允许删除文件，怎么防止误删？

`delete_file` 只接受普通文件，不支持目录或递归删除，并要求调用者提交文件当前内容的完整 SHA-256。模型通常先调用 `file_info` 获取摘要；如果文件在两次调用之间发生变化，摘要不匹配，删除会被拒绝。移动和复制也拒绝覆盖已有目标。这样保留了重构能力，同时把危险动作绑定到模型已经检查过的确切内容。

### 18. 为什么还要专用 Git 工具？

通用命令工具可以运行 Git，但专用 `git_status`、`git_diff` 和 `git_log` 更容易约束为只读操作。它们不经过 shell，diff 禁用外部差异程序和 textconv，路径仍经过工作区与敏感目录校验。模型因此可以低成本检查改动，而不必获得更宽泛的命令权限。

## 可主动指出的局限

- 字符预算不等于准确 token 数。
- 命令白名单可能拦截合法但少见的工具。
- 兼容网关的返回格式若偏离 OpenAI tool calling 约定，需要增加适配器。
- 没有系统级沙箱；不可信代码应在容器内运行。
- 当前是单进程连续会话，不支持多 agent 并行或会话恢复。

主动说明局限并给出演进方案，比声称“完全安全、完全兼容”更可信。
